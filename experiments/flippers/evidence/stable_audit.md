# 衝突・復帰処理の改善実験

2026-11-23 / Godot 4.7.2 `ed1daf0bf` / `flipper`

**実験と指定範囲の検証は終了したが、目標をすべて満たす採用構成は見つかっていない。** 通常接触の精度を維持し、停止板の開始重なりや移動Enemyとの停滞を改善できた。一方、深い復帰、狭い場所での繰り返し反射、未解消終了を同時に排除できなかった。本番反映は推奨しない。

本番の13ファイルは原因調査時のSHA-256と一致。本番変更、commit、push、Desktopへの複製は行っていない。3条件・新接触法線分離は引き続き実験上の基準である。

## 1. 提案する最小構成

次の構成を**次の改善の土台**とする。完成した本番候補ではない。

1. **時間を明示する移動照会。** 静止物にはGodotの `body_test_motion()` を使い、safe fractionを経過時間とする。travelに含まれる位置回復は時間から分ける。既存の壁・バンパーの反射、ダメージ、ノックバック、速度上限を引き継ぐ。
2. **同じ時刻のEnemy接触と応答。** 円同士の相対移動から接触時刻を直接求める。Enemyの更新後の形状を固定したまま平均速度だけ応答へ使う構成をやめる。回復・衝突があるEnemyでは、既存移動区間と瞬間的な回復を区別して記録する。Enemy自身の移動結果は変更しない。
3. **現在の分離状態を使う。** 完全分離を確認した後は更新開始の履歴だけで旧分離を選ばない。履歴の事実は診断用に残す。
4. **法線分離の余裕を周囲へ押し込まない。** 深さ＋0.15 pxを要求量とし、追加の分離変位が他物体を横切る場合は安全な範囲まで制限する。ただし、それで深さまで解消できなければ解決したとは扱わない。

1〜4を一緒にしただけでは③解除時の深い内部状態を安定して処理できない。通常接触の法線分離と、深い内部から復帰するゲーム規則は別にする必要がある。

Godot標準のtravel処理は、4.7.2の `PhysicsBody2D::move_and_collide()` にある `cancel_sliding` 相当の処理を照会部へ引き継いだ。これを省いた初期案では通常接触の終了位置に最大約0.024 pxの不要な差が出た。引き継いだ後は最大0.000123 px未満となった。コード中の0.001はこのエンジン処理の精度値で、新しいゲーム仕様のしきい値ではない。[4.7.2の該当実装](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/scene/2d/physics/physics_body_2d.cpp)

実装は [stable_motion.gd](../stable_motion.gd)、Enemyの時刻データは [enemy_path.gd](../enemy_path.gd)。周囲観測は [stable_environment.gd](../stable_environment.gd)。比較のため原因調査用クラスを継承しており、そのまま本番へ移植する部品には整理していない。

### 比較した構成

検出B、約4 px間隔、回転停止区間、3条件、返球方向・威力・反発、③、共有8接触、1ティック1更新を維持した。接触時刻で残り経路を再検査することと、ゲーム全体の追加時間分割を導入することは区別する。後者は行っていない。

| データ上の名前 | 変更点 |
| --- | --- |
| baseline | 3条件＋新接触法線分離＋現行解除。今回の比較基準 |
| state | 完全分離後の状態だけ更新 |
| clock | 標準照会と時間計算だけ変更 |
| state_clock | 上記2点 |
| relative | 上記＋Enemy更新前後の直線モデルによる同時刻接触 |
| normal | 上記＋独自接触の初期重なりも法線分離 |
| nearest | 上記＋解除前に近い法線方向へ安全分離。塞がれば未解消終了 |
| tangent | nearestにEnemyを横切らない接線方向の候補を追加 |
| bounded | normalに分離余裕の周囲による制限を追加。解除は現行 |
| bounded_tangent | bounded＋接線候補の解除前分離 |
| segmented | bounded＋Enemyの実移動区間・回復を分ける |
| segmented_tangent | segmented＋接線候補の解除前分離 |
| finish | segmented＋標準回復残りの追加法線分離と、8接触後の空経路照会 |
| finish_tangent | finish＋接線候補の解除前分離 |

`finish`系の追加法線分離と空経路照会は、一組の仕上げ案として評価した。各単独効果の分離まではしておらず、本番採用の根拠にはしない。接触応答は最大8回のまま。8回後の追加照会で9回目の接触を見つけた場合は処理を続けず、打ち切りを残す。時間を架空に進めてはいない。

Enemyの区間記録版は [tests/stable_enemy.gd](../tests/stable_enemy.gd)。元の `Enemy.advance()` と同じ移動・slide・ノックバック処理を行い、接触した場合だけ元の開始変換から読み取り専用照会を追加する。safe fractionによる実移動と回復の変位を分ける。元実装との48条件で位置差0.001 px未満・速度差0.01 px/s未満、追加照会対象の一致を確認した。回復を平均速度に含めないことは、Enemy速度を一律0にする方法とは異なる。

## 2. 改善結果

### 通常接触・開始重なり

| 試験 | 比較基準 | 改善案 |
| --- | --- | --- |
| 通常4,644条件 | 打ち切り0 | 検証した9構成すべて0。速度差0、終了位置差は最大0.000123 px未満 |
| 開始重なり288条件 | 打ち切り2、最大補正204.18 px | 法線分離を初期状態にも使う案は打ち切り0、最大48.15 px |
| ③解除の単独形状1,728条件 | 完走 | 検証9構成で未解消0。ただしEnemy・壁で塞がる配置を含まない |
| 球＋フリッパーのみ84入力 | 打ち切り0、最大補正2.19 px | 全14構成で同様。30／120 Hzでも打ち切り0 |

開始重なりの48.15 pxも小さい補正とは言えない。独自接触だけの法線変更であり、あらゆる初期重なりに安全な最短出口を保証したものではない。

通常4,644条件には30／60／120 Hzを含み、既知30 HzのID405／465／525も再確認した。B＋4・D2を使わず、Bの既存結果と比較している。Bに残る既知の検出誤差を解消したという結果ではない。

時刻を正しただけでは停滞が悪化する条件がある。終了位置だけのEnemyと速度応答の不一致を同時に扱う必要がある。60 Hzの板なし通常接触で既知4配置の打ち切りがなくなった点は、途中終了のない改善である。

一方、nearestの「打ち切り0」は17配置を途中終了させた結果であり改善とはしない。候補を増やすと未解消は減るが大補正が戻る。従来の無制限安全分離は既存記録で最大249.01 px・未解消3・打ち切り1。新しい接線候補でも、60 Hzの複数Enemy条件で最大約158〜164 px、30 Hzでは約199 pxの補正が残った。

共通完走入力だけでも集計した。`finish_tangent` と比較基準が共通完走したEnemy1体82入力では、打ち切り2→0。全環境＋3体の共通完走76入力では22→5だった。ただし候補側の未解消8入力はこの比較から除外されており、84入力全体が改善したとは言わない。共通完走76入力でリセット判定位置へ達した入力は17→15だが、軌道が変わるためこの差を安全性の証明には使わない。

### 更新終了時の重なりと後続更新

60更新まで追跡した。③で意図的に通過中の板内部を、通常の食い込みとは区別した。

* 全環境＋3体の比較基準では、更新終了時の対象形状との最大食い込みは約8.29 px。
* `segmented_tangent` では、完走入力における更新終了時の最大は約0.129 px。補正によって新しく作った干渉の最大深さは約0.013 px。
* `finish_tangent` では、この60 Hz条件の更新終了時の食い込みを検出しなかったが、途中の補正で最大約0.140 pxの新規干渉が残った。ほかの条件・更新率まで改善したわけではない。

回転中の板とEnemyを同時刻で測る案では、従来の終点姿勢だけで測る案と観測基準も変わる。新規干渉の単純なイベント数だけで採否を決めない。更新終了時の形状、実深さ、未解消、後続の反復を併記した。

各欄は84配置の「打ち切り／未解消」。接線案は `segmented_tangent`、仕上げ案は `finish_tangent`。

仕上げ案は120 Hzの通常接触で新しい上限到達を生んだ。全面採用しない。8回後の空経路だけ進める処理は一部の時間破棄を避けたが、実際に次の接触がある場合には解決しない。

## 3. 残る問題

### 解決または維持を確認した範囲

* 回復変位を時間へ投影する問題は、実験の標準照会側で分離した。raw safe fraction0の回復で時間を消費しない検査が通る。
* 完全分離後の状態を更新する処理を追加した。ただし現行解除の全体試験だけでは効果が小さく、これだけでは改善しない。
* 60 Hzの板なし通常接触で、相対的に離れているのに終点形状へ止められる既知4配置を解消した。
* 通常4,644条件の打球・反射速度を維持した。

### 部分的に改善した範囲

* 開始重なりの法線分離は大補正を減らしたが、周囲の安全を単独では保証しない。
* 接線方向の復帰は、旧候補の249 px横移動や停止板の未解消を減らした。ただし大きな瞬間移動と別の未解消が残る。
* 分離余裕の制限は、0.15 pxの押し出しで近い壁へ新しい食い込みを作る現象を減らす。ただしGodot回復自体や初期状態の深い重なりは別に残る。

### 未解決の技術課題

**狭い場所での実反射をどう連続して扱うか。** 30 Hzの板なし通常接触では `(ratio=.05, gap=12, offset=-36)` の既知配置に上限到達が残る。EnemyとLower壁の間で8回とも速度が変わり、接触時刻も進む。最後の時刻は約28.42 msで、33.33 msの更新の残りを捨てる。速度が変わらない同じ接触の単純な無視では解決できない。

接触時の法線制約を診断用に調べても、大半は速度上限内の非接近速度が存在した。したがって「周囲があるから物理的に解決不能」「8回を増やすしかない」とは断定しない。**複数接触を連続した拘束として扱う局所的な応答**は、今後の技術候補として残る。今回これを新たな共通フレームワークとして追加するところまでは行っていない。

**Enemy自身の回復残り。** 移動区間を正しく記録しても、元のEnemyが回復後に重なっている状態自体は変わらない。今回はEnemy挙動を変更せず、平均速度による誤った押し返しと回復残りそのものを分けた。区間記録化による改善幅は限定的で、これを全問題の解決とはしない。

### 復元比較の限界

原因調査の9状態を復元し、6構成×60更新を追跡した。54試行の介入前の球・Enemy位置、速度、③状態は一致した。

ただし停止板28.49／40.59 pxの旧8回反復は、復元した比較基準では同じ回数にならなかった。形状の生成・移動履歴、エンジンの回復照会の数値状態まで完全に復元できたとは確認できない。この2例の復元後の反復回数を、旧8回反復の改善証明に使わない。全84入力を初期状態から実行した試験を主要な根拠とした。以前の1秒後終了位置の不一致も引き続き既知の制約である。

## 4. 副作用・性能

### 挙動上の副作用

* 初期重なりも法線へ出すと、下面から上面へ貫通させる旧補正を避けられる。一方、球の復帰先が変わり、その後の軌道も変わる。
* 接線候補は直線経路と補正先の安全を確認するが、球が数十〜約199 px瞬間移動する問題を残す。軌道の自然さは未承認。
* nearestは保守的だが途中終了が多い。速いこと、上限到達が少ないことを利点には数えない。
* 標準回復残りを追加で法線へ出す仕上げ案は、終了時の深さを改善しても新規干渉や120 Hzの通常反復を増やした。既存回復の後に無条件で分離を足す方法は採用しない。
* 新たな解除延期や強制通過は追加していない。③で許可された上昇中の通過と、未解消終了、接触上限、リセット位置到達は別集計。

### CPUの参考測定

他の検証プロセスの終了後、同じ初期位置・速度へ毎回戻して球の1更新を測った。各条件20回ウォームアップ＋100回測定を4巡、構成の実行順を交互に反転した。全測定が完走し、同構成の位置・速度の再現を確認した。

移動Enemy1体の条件では、比較基準の中央値約123 µs・p95約218 µsに対し、区間記録を使う球側は中央値約154 µs・p95約267 µs。巡ごとの中央値にもばらつきがある。仕上げ案は約126 µsだったが、この差をアルゴリズムの高速化とは判定しない。

これは**観測コードを含む球1更新の測定**であり、Enemyの区間記録作成、群衆処理、描画、深い復帰候補探索の費用を含まない。平均値でゲーム全体の負荷を推定しない。Enemy記録側は接触があったときだけ追加照会するように削減した。総合的に正しい候補がまだないため、その候補の本番負荷まで測定できたとは報告しない。

## 5. 本番反映の見通し

**今回は本番反映を見送る。** 旧方式へ戻すためではなく、通常接触の改善と深い復帰の仕様・拘束応答を分けて次へ進むためである。

将来の変更箇所は次に限定できる見込み。

| 箇所 | 必要になる理由・注意点 |
| --- | --- |
| `pinball/motion.gd` | 標準safe fraction、回復変位、独自B時刻、残り時間を同じ基準にする。8接触の予算は維持 |
| 球の接触応答の入口 | Enemyの同時刻位置・速度を受け取る。既存の返球・威力・ダメージ式を共用し、実験の複製をそのまま残さない |
| Enemy移動・mainの受け渡し | 必要な移動区間を記録して球へ渡す。Enemyの実移動結果や群衆仕様を変えることとは別 |
| フリッパーの分離と③復帰 | 分離済み状態、初期重なり、復帰方針を整理。停止板と回転板で回復が違う点を隠さない |

今後は、技術課題である複数接触の拘束応答を小さな実験で評価することを優先する。通常接触が安定する前に、復帰の探索方向や履歴管理を増やし続けない。接線候補、標準回復後の追加分離、空経路照会は比較用の実験枝として保存するが、提案する本番最小構成へ自動的には含めない。

球同士の衝突、Enemy群衆管理、壁形状の作り直しは不要なままである。ただし最終候補ができた後に、観測・比較用の継承と設定分岐を外して部品を小さく整理し、再検証する必要がある。

## 6. ユーザー判断が必要な事項

次の事項を勝手に決めていない。

**深く内部にいた球の復帰で、どの程度の位置変更を許すか。** 同じ復元位置からの接線候補では、28.49 pxの重なりに約35.94 px、40.59 pxに約42.17 px、右側面24.49 pxに約53.92 px、12.16 pxの例に約19.90 pxの移動を使った。複数Enemyではさらに大きくなる。これは安全経路の候補であって、見た目として許容できるという判断ではない。

| 方針候補 | 利点 | 問題・未検証事項 |
| --- | --- | --- |
| 安全な位置補正を優先 | 下降で③を解除し、通常接触へ戻しやすい | 数十px以上の移動を許容するか。現在の候補には未解消も残る |
| 小さい補正を優先 | 位置が飛ぶ印象を抑えられる | 内部から出られない状態で、通過継続・短時間保留等を許すかは別途必要。無期限延期は採らない |
| 復帰時の軌道・周囲との関係を調整 | 出口へ自然に誘導できる可能性 | 意図的な軌道変更やEnemyへの影響がゲーム仕様になる。今回は実装していない |

この選択とは別に、30 Hzの板なし通常衝突の反復は技術的な未解決課題である。復帰仕様を選べば解決するとは言わない。また、上表から選ばない限り技術検討を進められないという意味でもない。

### 保存した検証と再実行

* 14構成×504統合試行＝7,056試行。各1秒、失敗候補は未解消で停止。
* 9構成×通常4,644条件、開始重なり288条件、単独③解除1,728条件。
* 30／120 Hz、5構成×各336試行＝3,360試行。
