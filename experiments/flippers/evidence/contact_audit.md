# 接触候補の実害と必要な処理の調査

2026-11-21。mainは変更していない。前回の「終点へ直線移動する方式を第一候補とする」という判断は撤回する。位置の近似だけでなく、敵へのダメージ対象が変わることを再現した。

## 現時点の判断

| 処理 | 判断と根拠 |
| --- | --- |
| 球の半径を含む直線経路の検査 | 基本として残す。静止した壁・板にはこれでよい。球に似た敵にも使う共通の移動部品が担当する |
| 動いている板を更新後の姿勢で固定して検査 | 単独採用を勧めない。現在の設定でも、非接触の球を打球し、返球方向・速度を変える。接触時刻で回転状態だけ直す追加案も取りこぼしを生んだ |
| 球と板を同じ時刻の途中姿勢で検査 | 回転中の板にだけ残す根拠がある。現在の4 px間隔の検査で、今回の分類対象874条件は誤接触・接触漏れ・打球状態の不一致0 |
| 全体の物理更新の細分化 | 今回の条件では外す候補。途中姿勢の検出は残す。前回の分離試験で成立し、検出・応答を細分化なしで追加調査した。全ゲームを移植した性能保証ではない |
| 接触後に残り時間の経路を調べ直す | 残す。直線経路は一接触ごとの区間で、反射後は接触点から別方向へ向かう。接触対象を正しく拾うために有用で、厳密な物理再現だけが目的ではない |
| 開始点から計算上の終点へ直接移動 | 採用しない。本来外れる敵に50ダメージ、本来当たる敵を無傷にする二例を再現 |
| 最大8回という反復上限 | 8が最適という根拠はない。ただし単純に2回で終了させる変更は残り時間を捨てる。食い込み解消の反復と、反射後の経路検査を分けて改善する対象 |
| 接触区間を追加で4回絞り込む | 任意の精度改善。現在の設定の接触後の終了位置差を最大2.73 pxから約0.19 pxへ減らした。今の数pxの補正を許容するなら必須にしない |
| 接触区間を12回絞り込む | 今回のゲーム要件で必要という根拠はない。回転中の数値精度は上がるが、静止物の標準判定・余裕幅を含む全体の最大位置差は4回版と同じ約0.19 px |

フリッパーは形状・時刻ごとの姿勢・打球状態を提供し、共通の移動部品が経路を調べる分担が自然。今の検証コードはボール継承スクリプトを利用しており、この共通化自体は未実装。

## 測ったもの

- 形状は左右X・下端を固定した四角形、追加厚み48 px。見た目の丸い端まで厳密に一致させる検証ではない。
- 既存の540入力を全件再計測。半径6/24/36 px、回転300/600/1,200°/秒、振り角18/45°、上昇・戻り、根元寄り・中間・先端寄り、下・上・横からの移動。
- 現在の設定に絞った336入力を追加。半径24、上昇600・戻り420°/秒、振り角18°、開始角0/3/6/9/12/15/18°。上辺20/65/95%付近、下向き300/1,200/3,600、上向き600/3,600、横向き±3,000＋下向き600 px/秒、静止。
- 各入力は開始時非接触。球の直線経路を固定し、重力・他の衝突・無効化を入れず、最初の接触と応答だけを比較。速度はその更新の重力適用後に相当する値として扱う。
- 既存入力の斜め3,600＋600は合成速度約3,650で上限3,600を少し超える。元の216件を検証するため入力を保存した。追加336入力は上限内。件数は後続の[標準のみとの再比較](native_audit.md)で生データを全件確認し、以前の48件という記述を訂正した。この記録の測定値は変更していない。
- 参照は測定専用4,096時刻の円と四角形の距離。最初に接触した区間を22回絞る。2,048時刻からも最初の時刻を求め、差0.01 ms未満を確認。参照は実験対象の衝突処理へ戻さない。
- 最小隙間が±0.1 px以内の2入力は誤接触・漏れ等の分類から除外。既存538入力に真の接触265、追加336入力に真の接触150。
- 静止した板は、途中姿勢版でも実際のGodot標準の移動判定を使用する。測定専用の参照判定に置き換えない。

別に、各入力を既存の移動処理で丸一更新動かす試験も実行。こちらは細分化なし、最大8回の接触処理、無効化③あり、重力0、速度上限3,600。非接触入力の正常な終了位置は直線移動だけで求められるため、それとの差を直接測る。

以下の「接触後の終了位置差」は最初の一接触だけを処理したときの位置差。「丸一更新の位置差」と、複数衝突を含む長期の軌道差を混同しない。意図的な0.15 pxの上向き分離や標準判定の接触余裕も含む。

## 「余分な48候補」の実害

| 結果 | 既存538入力 | 現設定336入力 |
| --- | ---: | ---: |
| 実際は非接触なのに候補が出る | 48 | 12 |
| そのうち実際に打球される | **15** | **1** |
| そのうち速度は変わらず位置だけ補正される | 33 | 11 |
| 実際の板と球の最小隙間（更新全体） | 2.06〜11.70 px | 1.45〜11.99 px |
| 誤打球を含む丸一更新の最大位置差 | 24.09 px | 7.47 px |
| 速度が変わらない例の丸一更新の最大位置差 | 19.00 px | 3.59 px |

すべてが無害な候補でも、すべてが誤打球でもない。速度が変わらない33/11例も、位置は動いていた。Godotの重なり回復を含む結果で、手動の上向き分離だけの量ではない。

### 現在の設定での具体例：非接触なのに約38.5°曲がる

データid **799**。左板が15°まで上がった時点、先端寄り95%。球半径24、上辺から中心を上へ36 pxに置き、上向き600 px/秒。次の1/60秒も左を押し、板は5 ms後に18°で止まる。

- 同じ時刻の形状で測ると、球と板は一度も接触せず、最小でも1.45 px空いている。
- 更新後の板で球の経路を検査すると2.23 ms時点の接触として扱う。その時刻の実際の板とは7.26 px空いている。
- 正常な速度は `(0, -600)` のまま。単純版は **`(525.8, -661.2)`、速さ844.8 px/秒**。約38.49°曲がり、速さが約41%増える。
- 丸一更新の終了位置は7.47 pxずれる。途中姿勢版は無接触・速度変更0・直線移動との差0。

これは見えない余裕幅だけの話ではなく、触れていない球への追加打球なので、実用上の問題と判断する。発生確率は測っていない。12/336等は狙って作った条件表の件数であり、プレイ中の発生率ではない。

## 候補数が一致していても、打球状態・位置が違う

現設定336入力で両方が接触を検出した150入力の比較：

| 指標 | 更新後の板＋球の直線経路 | 同時刻の途中姿勢 |
| --- | ---: | ---: |
| 接触時刻差の中央値／最大 | 3.73／10.90 ms | 0.36／8.04 ms |
| 接触点の最大位置差 | 38.56 px | 2.20 px |
| 両方で打球成立した例の最大返球角差 | 4.72° | **0.40°** |
| 通常反射も含めた最大角度差 | 120.87° | 9.81° |
| 接触後の終了位置差の最大 | 43.28 px | **2.73 px** |
| 打球の不一致（誤打球／打球漏れ） | 5／0 | **0／0** |

単純版の5誤打球は、非接触1例と、真の接触はあるが板が停止した後なのに打球扱いした4例。停止済みでも、その更新の平均角速度が上昇を示しているため。現行の「上昇中に打球する」仕様で分類した。停止後も打球を許す仕様に変えるなら後者の意味は変わるが、非接触の球が曲がる問題は残る。

接触位置が大きくずれる具体例はid556。休止中の左板、先端寄り95%、半径24、上辺から中心を上へ36 px、下向き300 px/秒から押す。参照の接触は3.98 ms後だが、単純版は更新後の板に最初から埋まった扱いになり、時刻0に約27.72 pxの位置回復を行う。返球角差自体は0.77°でも、最初の応答後の終了位置は38.99 px違う。丸一更新の比較でも左・右の終了位置に約40 pxの差が出る。粗い打球位置でよいことと、この位置回復を許容することは別。

**回転状態だけを接触時刻に合わせる追加案も比較した。** 更新後形状・標準判定の接触点と法線は保ち、その推定時刻の角速度で威力・打球可否を再計算。336入力で誤打球は5→1へ減るが、必要な打球を3入力で失った。形状を更新後へ固定したままなので、時刻自体のずれと誤接触は直らない。単純版に調整を加えた案を無検証で除外したわけではない。

途中姿勢版の9.81°は、戻り中の板で速さ約84.6 px/秒へ減速する通常反射の例（id758）。速度ベクトル差は約14.6 px/秒、終了位置差0.24 px。返球方向指定の誤差9.81°ではない。最大時刻差8.04 msも別の低速通常反射（id788）で、終了位置差0.40 px。角度や時刻だけで実害を判定しない。

既存の広い設定538入力では、途中姿勢版の接触後の最大位置差3.09 px、両方打球時の最大角差0.57°、最大接触点差2.58 px。誤接触・接触漏れ・打球漏れは0。すべての速度・かすり接触での保証ではない。

## 精度を上げる追加処理は必要か

最初に見つけた接触サンプルと、その一つ前の非接触サンプルの間だけを二分探索した。球・敵・重力などの物理更新を細かくする処理は追加しない。以下は最初の一接触の比較で、実ゲームへの統合はしていない。

| 現設定336入力での最大値 | 現在の4 px間隔の検査 | 接触区間を追加4回絞る | 追加12回絞る |
| --- | ---: | ---: | ---: |
| 両方打球時の角度差 | 0.399° | 0.027° | 0.00013° |
| 接触後の終了位置差 | 2.73 px | 0.19 px | 0.19 px |
| 手動上向き分離 | 3.01 px | 0.33 px | 0.15 px |

現在の形状・大まかな打球位置という要件なら、0.40°までの返球角差は小さい。数pxの位置補正を見た目として許容するかは別で、気になったら4回の絞り込みを足す余地がある。12回へ増やす必要性は見つからなかった。精密化だけで近接敵に挟まれた問題を解決する検証ではない。

## 終点へ直線移動する近似は、ダメージ対象を変える

球半径24、開始 `(964, 600)`、速度 `(2400, 1800)`、重力0。壁中心 `(1000, 600)`、幅6・高さ30、反発係数1。右の壁へ当たり、左下へ反射する。敵は実際のEnemy、半径30・HP100、固定配置、ダメージ50・速度加算0。

| 敵中心 | 接触点から折れ曲がった経路を検査 | 開始点から計算した終点へ直線移動 |
| --- | --- | --- |
| `(912, 582)` | 接触なし、ダメージ0 | **本来外れる敵に50ダメージ** |
| `(989, 660)` | 接触、50ダメージ | **本来当たる敵にダメージ0** |

敵は開始時に球・壁と重なっていない。前者の敵と本来の反射後経路は最小2.4 px空き、誤った直線は約1.42 px食い込む。後者は本来約1.8 px食い込むが、直線側では約1.64 px空く（接触余裕を含まない解析値）。どちらも標準の0.03 pxの余裕では説明できない。

これは「最終位置が少し違うだけ」ではない。この近似は採用せず、反射したら接触点から次の直線区間を調べる。球の経路を直線で扱う基本自体を否定する結果ではない。

## 接触反復はどこまで必要か

全体分割なし・途中姿勢検査・無効化③をそろえ、既存の接触ループの上限だけ2/4/8へ変更。近接敵84配置を各1秒、8回版をもう一度実行して再現性も確認した。

| 反復上限 | 残り時間を捨てた配置 | その更新数 | 捨てた時間の合計（84配置） |
| --- | ---: | ---: | ---: |
| 2 | 49/84 | 105 | 1,079 ms |
| 4 | 17/84 | 17 | 265 ms |
| 8 | 13/84 | 13 | 175 ms |

これは「3接触以上が49配置にあった」という数ではない。上限に達すると、最後の接触の後に自由移動できる場合でも残り時間を捨てる、現在のループの結果。例えば2回版では右板と穴縁への両方の接触で速度が変わり、まだ11.23 ms残っているのに終了する。2回という制限だけで合理的に簡略化できたとはいえない。

8回版にも問題は残る。根元寄り15%・敵との隙間3・横ずれ0の例では、板との接触後、敵→板→敵へ位置を約0.16 pxずつ補正し、最後は約0.01 pxへ減る。後半7接触で速度は変わらず、16.64 msを捨てた。

ただし、時間・速度・位置の全てが変化しない接触（時間1 μs未満、速度差0.01 px/秒未満、位置差0.001 px未満）は今回0。補正として働いている部分があるので、反復全体を無駄として削除しない。**反射後の経路検査と、挟み込みの重なり解消が同じ上限を使う構造**を改善する対象とする。8回が最適という証明ではなく、単純な回数削減も解決でないという結果。

20球×6秒の通常入力では2/4/8回の全てで上限到達0、打球53、定義した板下通過0。ここだけなら差が見えない。近接敵を別に調べる必要がある。長期の軌道は微小な判定差で分岐し、8回版同士でも1秒後の位置差最大0.25 px、20球試験では上限未到達でも別の実行条件との終了位置差が生じたため、それを回数による誤差として集計しない。CPUの小さな差から優劣も結論しない。
