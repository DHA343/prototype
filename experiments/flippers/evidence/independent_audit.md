# Bと全フリッパー独自検出B′の比較

2026-11-21、Godot 4.7.2。停止中の検出、開始時の重なりからの回復、応答・統合を分けて測定した。main、PinballMotion、TableFlipper、Enemy、返球計算、③は変更していない。C・Dの最適化も追加していない。

**今回は混合方式Bを維持する。約4 px間隔の既存検査を停止中まで広げたB′は、角のかすり接触を16条件で見逃し、壁より先に板へ当たる条件で接触順序も変わった。回復を全て上向きへ統一することも、側面・下面での大きな移動を生む。独自化そのものを不可能とする結果ではなく、今回のB′をそのまま採用しないという判断。**

## 実験構成

| 処理 | B：現在方式 | B′：今回の独自方式 |
| --- | --- | --- |
| 回転中と同じ更新内の停止後 | 既存の約4 px間隔・多角形検査 | 同じ検査をそのまま使用 |
| 最初から停止している板 | Godot標準 | 速度0の回転計画を作り、同じ検査を使用 |
| 標準移動クエリから除外する板 | 回転計画のある板、または③で無効の板 | 対象の衝突マスクに含む全ての板 |
| フリッパーの回復 | 回転接触は上向き16回、停止中は標準回復 | 全フリッパー接触を既存の上向き16回へ接続 |
| 壁・敵・バンパー | Godot標準 | Godot標準 |
| 返球計算・③・上限8接触 | 現行処理 | 同じ現行処理 |

実験用 [contact.gd](../contact.gd) は、停止中も既存の `Swing.sweep()` へ渡せる計画と、位置を動かさない問い合わせを提供する。戻り値は非接触・移動途中の接触・開始時の重なりに区分する。[motion.gd](../motion.gd) はこの計画を現行 `PinballMotion` へ渡すだけで、移動ループと応答計算を複製していない。

停止中の候補除外も、形状を含む支点中心の円を使う。新しい広域判定C、四角形専用計算D、接触区間の追加絞り込みは使わない。右板など衝突マスク外の板を、独自検査が拾わないことにも対応した。

測定用の派生クラスは位置・速度・接触履歴を記録するだけで、時間の細分化や回数変更はしない。実行時間は記録器を使わないクラスで別に測った。前回の `native_audit.gd` には、統合試験のモードを切り替える実験用フックだけ追加し、既存A/Bの既定動作は維持した。

## 1. 位置を更新しない接触検出

### 追加した停止中の2,016条件

- 左右それぞれの板、休止姿勢／18°保持、半径6/24/36 px、30/60/120Hz。
- 上面・右側面・下面・左側面の中央と4つの角。
- 外側0.2／12 pxから300／3,600 px/秒で接近、外側0.2 pxで静止・離れる移動。
- 角を高速でかすめる経路。最接近が0.2 pxの重なり、または0.2 pxの空きになるよう構成した。
- 他の障害物と反射・回復は使わず、標準側も `test_only=true`。全問い合わせの前後で球の位置・速度が変わらないことを検査した。

参照は前回と同じ独立した円・凸四角形の距離判定。4,096区間＋接触区間22回絞り込みを用い、2,048区間との接触時刻差0.01 ms未満を検査した。判定保留帯は±0.1 px。新しい2,016条件は全て保留帯外で、参照接触1,008件、非接触1,008件。

| 更新 | 分類数 | B 接触漏れ／誤接触 | B′ 接触漏れ／誤接触 |
| --- | ---: | ---: | ---: |
| 30Hz | 672 | 0／0 | 12／0 |
| 60Hz | 672 | 0／0 | 4／0 |
| 120Hz | 672 | 0／0 | 0／0 |
| 合計 | 2,016 | 0／0 | **16／0** |

漏れは全て半径6 pxの角へのかすり接触。接触区間がサンプルの間に収まってしまう。深さ0.2 pxの重なりなので、±0.1 pxの判定保留帯や標準余裕0.03 pxでは説明できない。120Hzで0件でも、任意の位相・速度で漏れない保証にはならない。

両方が参照接触を検出した条件での誤差：

| 検出値 | B | B′ |
| --- | ---: | ---: |
| 接触時刻差：中央値／95%点／最大 | 0.023／0.078／0.119 ms | 0.986／10.444／10.445 ms |
| 接触点の最大位置差 | 0.00013 px未満 | 0.00018 px未満 |
| 法線の最大角度差 | 1.255° | 14.839° |

角は接触点が同じ頂点でも、球の接触時刻が遅れると法線が変わる。接触点の誤差だけが小さくても応答は一致しない。時刻は低速で大きくなり得るので、時刻差単独をゲーム上の影響と読み替えない。

### 接触漏れの実際の影響

生データ `detection[87]`：左板休止、左上角、半径6、60Hz。開始中心 `(631.7119, 1016.6258)`、速度 `(2767.8306, -2301.9805)`、参照接触7.9066 ms後、最小隙間−0.2000 px。

同じ返球計算・標準移動へ接続して1更新動かしたところ、Bは通常反射し、B′は速度を変えず通過した。

| 結果 | B | B′ |
| --- | --- | --- |
| 終了速度 | `(2021.82, -2857.36)` | `(2767.83, -2301.98)` |
| 終了位置 | `(671.2857, 973.3781)` | `(677.8424, 978.2595)` |
| B/B′間の終了位置差 | 約8.17 px | 同左 |

方向差は約14.97°。この16条件はいずれも応答を実行し、履歴を `response` に保存した。Godot AIで起動したmain上でも同じ1更新を実行し、上表の位置・速度を再現した。動かす球の標準マスクから他の障害物を除き、実行後は元の停止状態へ戻した。

### 既存876入力の再利用

前回の876入力×30/60/120Hz、計2,628条件も再生。前回に合わせ、上限を超える216入力は3,600 px/秒へ制限した。参照は前回の各更新間隔で計算したものを再利用する。境界の11条件も生データに残し、分類集計では除外する。

- 全2,628条件で、Bの終了位置・速度が保存済みの現行部品による測定と一致することを検査した。許容差は位置0.001 px、速度0.01 px/秒。
- そのうち回転計画がある条件の検出値はB/B′で一致。分類対象における一更新の位置・速度も全て一致した。回転途中の検査を変更していないことを確認できた。
- 停止中は各更新間隔48入力。60Hzでは17入力で終了位置が変わり、B/B′間の最大差0.218 px、速度ベクトル差2.142 px/秒。30Hzは17入力・最大0.525 px、120Hzは6入力・最大0.718 px。
- この既存条件だけでは新たな接触漏れを見つけられなかった。角をかすめる追加条件が必要だった。

## 2. 開始時の重なりと回復

検出だけの問い合わせで、追加した288条件はB/B′とも全て「開始時の重なり」と分類した。位置は変更しない。

その後、回復だけを別に実行。左右×2姿勢×3半径×4辺と4角×3段階の深さ。指定深さは0.2／3／半径＋12 pxで、最後は中心も内部へ入る条件を含む。指定した辺以外の辺が最短になる場合があるため、指定深さを実際の最短分離距離とは扱わない。

標準側は零移動の標準クエリから回復移動量を取得し適用。上向き側は現行の16回二分探索＋0.15 pxをそのまま使用。解消または移動量0まで繰り返し、最大8回とした。これは回復だけの反復で、ゲームの移動時間を進める試験ではない。

| 回復結果 | Godot標準 | 上向き16回 |
| --- | ---: | ---: |
| 最初の補正距離の中央値／最大 | 2.636／41.804 px | 65.195／204.180 px |
| 累積変位の中央値／最大 | 3.022／48.015 px | 65.195／204.180 px |
| 回復問い合わせの中央値／最大 | 3／4回 | 1／1回 |
| 厳密な幾何で0.0001 pxを超える重なりが残る | 112件 | 0件 |
| 0.03 pxを超える重なりが残る | **0件** | **0件** |
| 最悪の最終隙間 | −0.00472 px | ＋0.01597 px |

標準側の112件は約0.001〜0.005 pxの残りで、移動余裕0.03 pxより小さい。これをゲーム上の回復失敗112件とは評価しない。0.0001 pxで残りを分類する厳しい測定値と、実用上の評価を区別する。

| 接触を与えた部位 | 標準の最大累積変位 | 上向きの最大累積変位 |
| --- | ---: | ---: |
| 上面 | 48.015 px | 48.968 px |
| 左右側面 | 48.015 px | 109.382 px |
| 下面 | 48.015 px | **204.180 px** |
| 上側の角 | 45.242 px | 46.148 px |
| 下側の角 | 44.501 px | 200.063 px |

最大204.18 pxは、18°保持・半径36・下面への浅い0.2 pxの重なり。上へ出すには四角形全体を横切るためで、16回の探索誤差ではない。上向き回復の方針を停止中の下面にも適用すること自体が、結果を大きく変える。回復回数が少ないことだけで優れているとは判断しない。

補助確認として `recovery_as_collision=false` の実移動も実行した。288条件全てで位置は変わった。衝突報告フラグを変えるだけで回復実行を外せないことも確認した。

## 3. 同じ応答処理での統合

両方式とも現行の返球・反発・③・接触上限8回を使用。B′の停止中接触は既存の上向き回復へ接続したため、下記の位置差は検出と回復の両方を含む。検出だけ・回復だけの評価は上の段階で分離した。

### ③解除・停止への切り替え

内部にいる球のY速度−1 px/秒に重力を適用し、次の更新で③が解除される条件を用意。休止・18°保持・上昇中を分けた。

| 条件 | B/B′間の終了位置差 | 観測 |
| --- | ---: | --- |
| 休止中に③解除・板内部 | 6.63 px | 返球速度はほぼ同じ、回復方向・量が違う |
| 保持中に③解除・板内部 | 4.75 px | 同上 |
| 上昇中に③解除・板内部 | 0 px | 同じ途中姿勢検査・上向き分離・再打球 |
| 更新途中で回転停止 | 0 px | 同じ独自検査が更新の終わりまで続く |
| 停止後の次の更新・埋まりあり | 0.56 px | Bは標準回復、B′は独自回復 |

上昇中の例は解除後に再打球して再び③が有効になる。「終了時も無効化中」というだけでは、解除されなかったとは判定しない。これら5条件は各方式で1更新の例であり、全ての③解除位置の保証ではない。

### 壁と板の接触順序

休止中の上面と垂直な試験壁に対し、同じ円の直線移動から各接触時刻を幾何的に求めた。最初は板にも壁にも非接触。両方式ともGodotの壁接触と独自側の板接触を、同じ更新開始からの秒で比較する。

板の参照接触時刻は5.6045 ms。壁を板より−2／−0.1／0／＋0.1／＋2 msで接触する位置へ配置し、各方式を再生した。差±0.2 ms未満はほぼ同時として別扱いにする。

| 壁の参照接触時刻 | 参照の先着 | Bの先着 | B′の先着 |
| --- | --- | --- | --- |
| 板より2 ms早い | 壁 | 壁 | 壁 |
| 板より2 ms遅い | 板 | 板 | **壁** |

壁が2 ms遅い条件で、Bは5.5990 msの板を先に処理した。B′は標準クエリで壁に届く7.5521 msまでを検査したが、その間の4 pxサンプルでは板との接触を拾えず、壁を先に処理した。単位・時刻原点の不一致ではなく、接触時刻を粗くサンプルする影響。±0.1 msと同時の条件は採否の誤順序件数へ混ぜない。

### 複数球・近接Enemy

実際のmain配置の壁・バンパー・左右板・穴を使用。初期配置は壁・バンパーと非接触。③あり、重力1,500、上限3,600、全体時間分割なし、球同士の衝突なし。Enemyは既存の独立移動を維持する。

| 20球×6秒 | B | B′ |
| --- | ---: | ---: |
| 打球数 | 38 | 33 |
| 上限到達更新 | 0 | 0 |
| 定義した板下通過 | 0 | 0 |
| 最大位置補正 | 58.55 px | 70.54 px |

1球×6秒も実行したが、両方式で打球0のため、回転接触の有効性を示す根拠には使わない。板下通過の定義は前回と同じで、板の下端＋半径を下へ横切る位置が、板の左右端から半径ぶん内側にある場合。これは有限の観測指標で、全てのすり抜けの保証ではない。

| 近接Enemy84配置×各1秒 | B | B′ |
| --- | ---: | ---: |
| 移動打ち切りが起きた配置 | 3/84 | 4/84 |
| 打ち切り更新数 | 3 | 4 |
| 捨てた時間の合計 | 25.80 ms | 42.80 ms |
| 最大位置補正 | 68.39 px | 136.84 px |

停止中の検出・回復が変わると長期の経路も分岐する。統合には高精度の全経路参照がないため、打球数や配置数だけで正確性の優劣を決めない。今回のB′を採用しない直接の根拠は、単独試験の接触漏れと、時刻が明確に分かれた条件の接触順序。統合の数字は大きな補正・打ち切りが解決しなかったことの記録とする。

前回の20球試験のBの打球37と今回38のように、わずかな実行差からも長期軌道は分岐する。今回のB/B′間の打球差を、全て停止中の独自化による一定の効果とみなさない。

## 処理負荷・単純さ

記録器なしで、前回876入力の1更新を60Hzで計測。位置・形状のリセットと参照計算は時間外。1巡ウォームアップ後7巡、B/B′の実行順を交互にした。

| 876入力の合計時間 | B | B′ |
| --- | ---: | ---: |
| 中央値 | 61.025 ms | 66.261 ms |
| 最小〜最大 | 59.036〜70.887 ms | 62.136〜73.273 ms |

この入力分布ではB′は約8.6%遅く、軽量化の効果はなかった。本番1フレームや全ゲームの性能ではなく、単独更新のバッチ比較。前回の測定時間との小さい違いも性能改善として扱わない。

B′は既存の移動ループを再利用でき、停止中／回転中を同じ経路に統一できる。しかし、停止中のかすり接触、壁との順序、下面からの回復を正しく扱うには追加の対策が必要で、現時点で単純化の利益が精度低下を上回る根拠はない。

## 採否と残す判断

- **現在の混合方式Bを維持する。B′は検証用として残し、本番へ採用しない。**
- 停止中の標準判定を外せば回復問題が消える、という結果にはならなかった。現行Bにも統合の大きな分離と打ち切りが残る。
- 回復方式の変更は検出方式の独自化と別に判断する。全接触を上向きに統一する案は、下面で約204 pxの移動を生むので、そのまま拡張しない。
- B′の接触漏れは、最初の接触サンプル自体が存在しない条件。検出済み区間だけを二分探索しても、この漏れは救えない。停止中まで独自化を再検討するなら、角を含む連続経路検査など、漏れを防ぐ仕組みが比較対象になる。
- C・Dは今回は実装・比較しない。今後比較する場合も、停止中のGodot標準を残したまま、回転中の候補除外Cと接触計算Dを個別に検証できる。B′採用はその前提ではない。
