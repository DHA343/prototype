# 打角・フリップ速度を変えた③の比較と接触反復の調査

## 結果

無効化なしと③「打球後、下降まで左右を通す」を同じ初期状態で比較した。先端打球の直後に反対側の通常反射で上寄りへ曲がる現象を再現し、③ではその干渉を防いだ。一方、遅いフリップでは球が内部にいる間に下降へ転じ、解除後に再打球される例がある。③の採用候補としての評価と、解除時の内部接触の問題を分ける。

| 比較内容 | 無効化なし | ③ 下降まで | 補足 |
| --- | --- | --- | --- |
| 上昇中に反対側の通常反射で速度が変化した条件 | 510/1,800 | 0/1,800 | 最初の打球後、外部の壁などへ当たる前の接触を対象とする |
| うち、通常反射で上方向へ近づいた条件 | 508/1,800 | 0/1,800 | 反射前後の上方向からの角度差を比較 |
| 上昇中に反対側で再打球された条件 | 126/1,800 | 0/1,800 | 上の通常反射の件数とは重複する条件があり、合算しない |
| 最初の打球の速度 | 全条件で同一 | 全条件で同一 | 返球角を調整して回避した比較ではない |

件数は設定を組み合わせた条件数で、通常プレイでの発生率ではない。検査は5,580件で失敗0だが、確認したのは最初の打球の一致と上昇中の直後の干渉抑制など。解除後の内部接触が解決したという判定ではない。

## 具体的な再現

- mainと同じ配置、穴84 px、半径24 px、重力1,500 px/s²、追加厚み48 px。
- 振り角18°、上昇速度300°/s、根元返球角−20°・先端返球角70°。
- 左上辺の先端寄り90%から、球を上へ半径＋4 px離し、下向き300 px/sで開始。左右を同時に押して保持。
- 約2.78 msで左が打球。球の速度は約(1,261, −742) px/s、上方向から右へ約59.5°。
- 約72.54 msで、すでに停止した右フリッパーの端付近へ接触。通常反射の直前は約(1,261, −636) px/s、右へ約63.2°、反射後は約(354, −1,033) px/s、右へ約18.9°になった。
- この右接触は方向指定の再打球ではなく、標準衝突経路の通常反射。③では同じ最初の打球から進み、右への接触処理は発生しなかった。

「右斜めへ打つ→右の通常判定で少し右寄りの上へ変わる」という報告に対応する再現。上昇速度600°/sでも同じ設定で右へ約60.5°→約35.5°の通常反射を確認し、③では抑制した。

現在の初期設定である振り角18°・先端返球角40°・速度600°/sだけに限定した24条件では、無効化なしでも対象の通常反射による方向変更は出なかった。元の報告時の設定がこの値だったと確定したわけではない。

## 条件の範囲

| 変更項目 | 値 |
| --- | --- |
| フリッパーの振り角 | 18 / 30 / 45° |
| 先端の返球角 | 0 / 20 / 40 / 60 / 70°。根元は−20°で固定 |
| 上昇速度 | 90 / 180 / 300 / 600 / 1,200°/s |
| 反対側の状態 | 同時押し、20 ms先行、上げ終わり、15 ms遅れ、30 ms遅れ、上げた状態から戻す |
| 球の開始位置 | 打つ側の先端寄り90 / 99%。左右を反転して両方検証 |
| 追跡時間 | 直後の比較1,800条件は各250 ms。追加60条件は各2秒 |

追加60条件は、振り角18/45°、先端返球角40/60/70°、全5速度、同時押し／反対側の上げ終わり、左の先端寄り99%を追跡。最初の250 msだけで下降復帰の安全性を判断しないために行った。

## ③に残る懸念

### 内部にいる間の下降解除

実際の打球から進めた1,800条件中、90/180°/sの60条件で、解除時に球がまだフリッパーと重なっていた。そのうち30条件で解除した内部更新中に新しい打球が発生した。球を内部へ直接配置して始めた人工試験ではない。

例：振り角18°・先端返球角60°・速度90°/s・左先端寄り99%・同時押し。左の打球後に右へ進み、約179 msで下降へ転じた時点で右に約7.48 px食い込んでいた。解除した内部更新で球が上へ約44 px動き、右の打球が発生した。

追加の2秒追跡でも90/180°/sの14/60条件で内部解除、4条件で解除時の打球を確認した。300/600/1,200°/sでは、今回の直後比較と2秒追跡の範囲で内部解除を検出していない。低速では打球も弱くなる現状の威力計算が関係するため、移植時の返球速度の調整仕様と合わせて確認する。

その後の [現設定で近くの敵を追加した確認](current_guard.md) では、600°/sでも内部解除を検出した。敵あり84条件中22条件で内部解除、解除した更新での新規打球は0。上の未検出という結果は敵の至近距離からの戻りを含まない試験範囲での結果であり、現設定で内部解除が起こらないことを示さない。

③を基準とする場合も、内部から接触を復帰させる処理と、新しい接触による打球を区別する対応を検討する。今回の比較では解除条件・接触処理自体を修正していない。設定を広げた今回の最大上向き分離距離は約104.18 pxだった。

### 下降しない状態

上向きのまま横壁等で戻った球には、③の無効化が続く。また、今後、重力なしで上昇し続ける対象や下降しないAI移動を追加すると、下降条件だけでは解除されない。ボールと同様に動く対象を共通化する際に、この解除条件を適用する範囲を決める。

## 接触反復の原因

1内部更新の残り時間で「壁で反射→別の壁やフリッパーに接触」を順に処理する枠組みは必要。同じ接触を進展なく8回扱うことは必要な仕様ではない。

停止した右フリッパーで8接触に達する更新を再現し、各回の接近速度・残り時間・移動量を記録した。

- 1回目は接近速度約5.53 px/sで反射し、残り時間は約0.0248 msになった。
- 2〜8回目は接近速度約−0.65〜−0.92 px/s。すでに面から離れる方向なので、`_resolve_contact()` は反射せず終了した。
- 一方、`move_and_collide(..., recovery_as_collision=true)` は食い込み解消を含む接触を返す。残りの移動の長さは0.001 px未満で、`_advance_motion()` はその接触の経過時間を0として扱う。
- 残り時間も速度も進まず、同じ面を再検査して8回の上限へ達した。上げ終わりの姿勢でも同じ構造を確認した。

今回の反復は、衝突後の残り時間を処理する必要性を起点にしているが、離れる接触・微小移動・進展しない場合の終了条件が十分に整理されていないために生じる。共通移動部品への移植時は、複数衝突の処理を保ちつつ、この余分な反復を改善対象にする。今回、本体の衝突ループは変更していない。
