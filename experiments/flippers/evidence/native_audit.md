# Godot標準だけの構成と途中姿勢検査の比較

2026-11-21。Godot 4.7.2、GDScript、headless。同じ現行 `PinballMotion` へ回転情報を渡さないAと、渡すBを比較した。main、本番の移動・フリッパー処理、Enemyの処理は変更していない。

**標準判定だけのAは、現設定でも非接触の球への打球と大きな位置補正を起こしたため、そのままの採用には不十分。Bは今回の単独接触の分類対象で誤接触・接触漏れ・打球状態の不一致0。ただし、近接敵との統合ではBにも反復上限と大きな位置補正が残る。**

## 比較した構成と既存記録の訂正

既存 `contact_audit.gd` の `frozen` も、すでに Godot標準の `move_and_collide(..., test_only=true)` を使っていた。更新後の板に対する独自の幾何検出だけの方式ではない。`cast_motion()` の有無は別に記録されており、応答に使う点・法線・移動量は `move_and_collide()` から取得していた。

今回は旧実験の `legacy_motion.gd` や打球履歴を使わず、mainのシーンをロードし、実際の `PinballBall` / `TableFlipper` / `PinballMotion` で再計測した。測定器は接触応答の前後を記録する派生クラスで、移動ループ自体は複製していない。

| 項目 | A：標準のみ | B：現在の検出 |
| --- | --- | --- |
| 球の移動 | 同じ `PinballMotion` | 同左 |
| 回転情報 `swings` | 空の型付き配列 | 左板の回転計画を渡す |
| 回転中の板 | 更新後の形状へ `move_and_collide()` | 同時刻の途中姿勢を約4 px間隔で検査 |
| 最初から停止している板 | Godot標準 | Godot標準 |
| 形状・厚み | 同じ固定四角形・追加48 px | 同左 |
| 返球・反発・速度上限 | 現行の処理・上限3,600 px/秒 | 同左 |
| 回復 | Godot標準の回復 | 回転検査の接触は既存の真上分離、その他は標準回復 |
| 反射後の移動 | 接触点から残り時間を再検査、最大8接触 | 同左 |
| 全体時間分割・追加の接触区間絞り込み | なし | なし |

「標準だけ」を保つため、Aへ手動上向き分離は追加しない。したがって回復の経路は完全に同じにはならない。検出の分類を独立に数え、位置・速度の結果には回復の影響も含める。16回の分離探索、③、上限8回の変更や最適化は行っていない。

## 入力と参照

- 既存876入力を60/30/120Hzで再生し、計2,628条件を計測。旧540入力と、現設定336入力を分けて集計した。
- 旧540入力：半径6/24/36 px、上昇300/600/1,200°/秒、振り角18/45°、上昇・戻り、接触位置・速度・進行方向を変更。現設定336入力：半径24、上昇600・戻り420°/秒、18°、開始角0/3/6/9/12/15/18°。保持状態は回転計画がない条件に含む。
- **旧入力の斜め速度 `(3600, 600)` は48件ではなく216件。** 生データ全件で確認した。今回は本番と同じ速度制限をA/B/参照の全てに適用し、約3,650→3,600 px/秒とした。現設定336入力に速度制限で変わるものはない。元の位置・速度は生データに併記し、旧記録は上書きしない。
- 最初の検証は左板1本だけを衝突対象にする。壁・右板・敵・バンパーは球の検出マスクから除外。開始時非接触、重力0、球同士の衝突なし。入力速度は当該更新の力の適用後に相当する値として扱う。
- 参照は円と四角形の距離を4,096区間で検査し、最初の接触区間を22回絞る。2,048区間からの時刻と0.01 ms未満で一致することを検査した。凸四角形の内外判定は半平面の符号、外側の距離は4辺との距離を使う。
- 参照を各更新間隔で再計算した。60Hzで速度制限によらない660入力は、保存済み参照との接触有無・打球状態の一致も検査した。
- 最小隙間が±0.1 px以内の条件は分類から除外し、生データには残す。60Hzは874、30Hzは874、120Hzは869条件を分類した。これはGodotの0.03 pxの移動余裕より広い判定保留帯で、全てのかすり接触を保証するものではない。

「最初の応答」は③なしで取得。実際の移動ループの最初の接触時点を保存し、その後を自由移動した場合の終了位置を求める。実際の一更新全体は別に③を有効にして取得した。最初の応答後の位置差と、複数接触した一更新全体の位置差を混同しない。

### 現設定60Hzでの実害・誤差

参照と両方が接触した150件、両方が打球した103件を比較。

| 指標 | A | B |
| --- | ---: | ---: |
| 非接触候補のうち実際の誤打球 | 1件 | 0件 |
| 非接触候補のうち速度を変えず位置だけ補正 | 11件 | 0件 |
| 非接触条件の一更新全体の最大位置誤差（③あり） | 7.47 px | 0 px |
| 最初の応答後の終了位置差：中央値／95%点／最大 | 15.18／41.20／43.28 px | 0.39／1.62／2.73 px |
| 接触点の最大位置差 | 38.56 px | 2.20 px |
| 両方打球時の角度差：中央値／95%点／最大 | 0.869／4.116／4.725° | 0.058／0.291／0.399° |
| 接触速度ベクトルの最大差 | 5,041.02 px/秒 | 25.18 px/秒 |
| 最初の応答の最大位置補正量 | 27.72 px | 3.01 px |
| 一更新全体で上限8回に達して時間を捨てた入力 | 22件 | 0件 |
| その破棄時間の合計（336入力） | 125.28 ms | 0 ms |

位置補正量は誤差そのものではない。測定器は推定接触位置から実際の応答位置への差を記録する。Bの回転接触では既存の上向き分離量、Aでは標準回復を含む移動結果の差になる。Aの接触時刻は標準移動の `travel` を進行方向へ射影して推定するため、開始時回復を含む条件では実際の幾何接触時刻とは異なる。

- **id799：非接触の球が曲がる。** 球は一度も板に触れず最小隙間1.45 px。Aは `(0, -600)` を `(525.805, -661.200)` へ変え、速さ600→844.78 px/秒、方向約38.49°、一更新の終了位置7.47 pxずれ。Bは速度・直線移動とも変更なし。③ありでもAの誤打球は防げない。
- **id556：接触位置・回復の大きなずれ。** Aは更新後の板に開始時から埋まった扱いになり、最初の応答で約27.72 pxの補正。Editor上の既存再生でもA/Bの一更新終了位置は39.11 px異なる。これは参照との誤差ではなくA/B間の差。
- **id613：小さい反復でも移動打ち切りになる。** Aは通常反射後に同じ板との標準接触を繰り返し、後半7接触で速度は変化しないが位置・経過時間は変化する。8回で残り1.54 msを捨てる。全てが無処理の反復という意味ではない。履歴は `cap_trace` に保存した。
- **30Hzのid409/469/529：接触漏れ。** 半径36、45°から戻る板、中央寄り65%を斜めに横切る条件。参照の最小隙間約−0.99 pxで、曖昧帯外。Aは速度 `(3551.018, 591.836)` のまま通過し、Bは通常反射する。3条件は開始までの上昇設定が異なるが、戻り速度は共通420°/秒なので、異なる3種類の現象ではない。

## 30/120Hzと許容範囲

| Bの入力群 | 更新 | 最初の応答後の最大終了位置差 | 両方打球時の最大角度差 |
| --- | --- | ---: | ---: |
| 現設定 | 60Hz | 2.730 px | 0.399° |
| 現設定 | 30Hz | 2.970 px | 0.414° |
| 現設定 | 120Hz | 2.605 px | 0.399° |
| 旧設定の広い範囲 | 30Hz | 4.135 px | 0.610° |

前回の暫定案「位置差3 px、打球方向差0.5°」は、現設定の単独接触について今回の30/60/120Hzでも超過0。広い設定の30Hzでは位置差9件、方向差8件が超える。したがって、この基準を全半径・回転設定の保証として採用しない。

mainは1920×1080座標を640×360で描画するため、3 pxは描画上の1ドット相当、4.135 pxは約1.38ドット相当。ドット未満なら必ず見えないという意味ではなく、ラスタライズの境界や後続の接触対象は変わり得る。通常反射で速さが小さくなる条件では角度差が大きく見えるため、速度ベクトル差・位置差も併記して評価する。

追加4回の接触区間絞り込みは既存監査での候補として残るが、今回は追加・比較しない。検出漏れや非接触への打球を許容するために位置・角度のしきい値を緩める判断もしない。

## 処理負荷

検査回数は計数器付き、実行時間は計数器を外した実際の `PinballMotion` / `TableFlipper` で別に測った。60Hz・876入力を1巡ウォームアップ後、A/Bの測定順を交互にして7巡。時間に参照計算・リセット・設定・ファイル出力を含めず、球の `advance()` 全体を含む。

| 時間（876入力の合計） | A | B |
| --- | ---: | ---: |
| 中央値 | 21.013 ms | 64.328 ms |
| 最小〜最大 | 18.465〜28.701 ms | 61.341〜102.020 ms |
| 中央値の巡回での1入力平均 | 23.99 μs | 73.43 μs |

| 現設定336入力・③ありの検査回数合計 | A | B |
| --- | ---: | ---: |
| 標準移動クエリ | 640 | 487 |
| 検出用の独自円・四角形接触計算 | 0 | 4,684 |
| 分離用の独自接触計算 | 0 | 2,312 |

標準移動クエリ数は、現行ループの接触イベントと終了条件から復元した数。独自接触計算は `_contact_at()` の呼び出しを直接計数した。両者は1回あたりの処理量が違うので、合算して同じ重さの検査回数とは扱わない。

Bはこの対象分布でAの約3.06倍、1入力平均で約49.45 μsの追加時間。ただしAは誤応答や残り時間の破棄もするので、正しい処理を同量行った比較ではない。単独試験の集計であり、本番1フレーム・20球全体・描画やEnemy AI込みの所要時間に読み替えない。CPU時間のばらつきもあるため、これだけで4 px間隔が性能上必要／不要とは判断しない。

## 統合試験

実際のmain配置の左右板・穴・壁・バンパーを使用。③あり、重力1,500、上限3,600、全体時間分割なし。球同士の衝突はなし。Enemyは実際のクラスを使うが、共通移動部品へ変更していない。

### 1球／20球を6秒

固定乱数種11000＋球番号で初期値を再現。壁・バンパーなどと重ならない候補を選んで開始した。左右を0.55秒周期・0.08秒押下、右は0.275秒ずらす。

| 球数 | 方式 | 打球数 | 上限到達更新 | 定義した板下通過（衝突有効／③で無効） | 最大位置補正 |
| --- | --- | ---: | ---: | ---: | ---: |
| 1 | A | 0 | 0 | 0／0 | 0 px |
| 1 | B | 0 | 0 | 0／0 | 0 px |
| 20 | A | 35 | 0 | 0／0 | 34.40 px |
| 20 | B | 37 | 0 | 0／0 | 58.55 px |

1球試験では打球が起きなかったため、回転接触の有効性を示す結果として使わない。板下通過は記録した移動区間が `fixed_bottom + radius` を下へ横切り、そのXが板の左右端から半径ぶん内側の場合を数える。③による意図した通過を分けた有限の観測指標で、すり抜け全体の保証ではない。

20球試験ではA/Bとも大きな位置補正が残る。単独接触の2.73 pxという参照誤差とは別の量であり、統合の補正を3 px以内に抑えられたという結論にはしない。

### 近接Enemy84配置を各1秒

接触位置7通り×敵との隙間3/12/36/72 px×横ずれ−36/0/36 px。球と敵は開始時非接触。Enemyの通常移動・被弾・ノックバックは既存の処理を使い、敵への共通移動適用は行わない。

| 方式 | 反復上限に達した配置 | その更新数 | 破棄時間合計 | 最大位置補正 |
| --- | ---: | ---: | ---: | ---: |
| A | 0/84 | 0 | 0 ms | 52.55 px |
| B | 3/84 | 3 | 25.80 ms | 68.39 px |

この統合には高精度の全経路参照がない。A/Bは早い段階の接触・打球が違い、後の配置も分岐するため、上限到達0のAが正しい／優れているという評価はしない。旧記録の13/84と今回の3/84も、旧互換処理・main配置・打球履歴等が違うので単純な改善率として扱わない。

Bの最大68.39 pxの例は、先端99%・隙間12 px・横ずれ0で、右板側面との回転接触を真上へ分離したもの。上限到達の例とは別条件。今回維持した上向き分離や③を含む統合の課題として、生データの `max_correction_event` と `cap_trace` に分けて保存した。今回これらの処理は変更していない。

## 結論と次に切り分ける対象

1. **Aをそのまま採用しない。** 現設定で非接触の誤打球、停止後の誤打球、大きな位置回復を再現し、広い設定の30Hzでは接触漏れも確認した。検出数が多いだけの問題ではない。
2. **回転中の形状と球の時刻を合わせる検出には、残す根拠がある。** Bの構成では今回の分類対象に不一致0。ただし、これだけで4 px間隔・停止時刻での区切りの各々が最小限だとは証明していない。
3. **次の削減比較は検出の構成要素に限定する。** 同じ入力と参照で、途中姿勢を残したまま検査間隔と停止時刻の区切りを個別に変更する。接触区間の追加二分探索を先に入れる必要はない。
4. **統合の大きな分離・移動打ち切りは別課題。** Bの単独接触の精度がよいことを理由に、近接敵や③解除後の回復まで解決済みとはしない。16回や8回を減らす変更も行っていない。
