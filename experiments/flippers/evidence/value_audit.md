# 衝突問題の実害と改善コスト

2026-11-23 / `flipper` / Godot 4.7.2 `ed1daf0bf` / Windows・headless・60 Hz

**現時点の推奨は、通常の新接触だけを法線分離する小さな変更を優先し、承認済みの3条件打球と組み合わせること。時間・Enemy・復帰の仕組みを一括導入する段階ではない。** 大きな補正は実シーンでも発生した。一方、本番相当18分で接触上限は2更新で、どちらも後続更新で移動へ戻った。これを恒常的な停止として全面改修する根拠はない。

これは採用価値の評価であり、本番反映ではない。本番13ファイルのSHA-256は原因調査時と一致。commit・push・Desktopへの複製は行っていない。観測した件数は人間の通常プレイの発生率ではなく、下記の自動操作条件における件数である。

集計は [value_summary.json](value_summary.json)、測定一覧は [value_isolated_manifest.json](value_isolated_manifest.json)。既存の [separation](separation_audit.md)・[causal](causal_audit.md)・[stable](stable_audit.md) の人工条件と、今回の実シーン測定を区別した。

## 1. 現在の問題の規模

### 測定した環境と比較の範囲

実際の `main/main.tscn` を読み込み、元の `main.advance()` を1物理ティックに1回呼ぶ。球半径24 px、重力1,500 px/s²、上限3,600 px/s、フリッパー18°・600°/s、厚み48 px、③、共有8接触を維持。Enemyは元の速度30 px/s、1秒ごとの生成、経路・成長・群衆・死亡・退出を実行する。壁、バンパー、ダメージ、ノックバック、バンパー起動のミサイルも維持する。

球は元の落下判定で非稼働になり、0.45秒後に元の位置(780, 540)へ再生成する。Enemy数は固定せず自然に増減する。本番相当Aの平均10.72体・最大54体、比較全体の最大58体。フリッパー近くへEnemyを強制配置していない。

音声再生とShotGuideを停止し、描画なしで測った。したがって描画込みのFPS、予測ガイド、音声処理の費用は今回の時間に含めない。Enemy生成は元の一様抽選・最大試行回数を使うが、生成機会ごとに独立した乱数種を与え、音声等の乱数消費と切り離した。元のグローバル乱数列そのものの再生ではない。

### 具体的な実害と、被害が限定的だったもの

* **新接触の93.41 px補正。** A・保持・種113の更新2853。右板との新接触で真上に移動し、その後も同じ更新内で数pxずつ補正した。8回へは達していない。約1秒以内に落下・再生成したが、補正が落下の原因だったとする対照は成立していない。93 pxの瞬間的な位置変更そのものは、上限数だけでは捉えられない問題である。
* **上限到達は2種類だった。** A・自己反応・種113の更新5677は同じEnemyに8接触し、速度変更0回、補正最大約0.051 px。更新末の未実行経路時間の推定は約0.502 ms。種809の更新6891はバンパーとEnemyに交互接触し、8回とも速度が変わり、約5.572 ms残った。両方とも連続上限は1更新で、1秒後も稼働中。接触無視や単純な上限増加を同じ処方にしない。
* **長時間停止は観測しなかった。** Aで「接触中、速さ30 px/s超、更新間移動0.03 px以下」の連続更新は0。接触を伴う移動方向の反転は最大3更新で、これは正当な跳ね返りも含む診断値。すべての低速停滞や見た目の振動を否定する検査ではない。
* **時間の誤計上は上限到達以外にもある。** A・保持・種113では再生成先にEnemyがいる2回を確認。次の更新4902/5409などは標準回復1接触で現行の投影時間が全更新分に達し、実移動のsafe fractionは0だった。要求移動を実行せず終了している。更新4902の回復変位は約20.51 px。一方、当時の球速度は25 px/sで、未実行の自由移動量は約0.42 pxに相当する。16.67 msという時間だけで被害を過大評価しない。
* **周囲への押し込みは残る。** Aで補正による新規干渉候補1イベント、経路だけ横切る候補0。最初の計測版では小さい干渉だけの詳細保存が不十分だったため、この1件の深さ・重大性は不明。保存条件を修正した追加の同seed試行では再現しなかった。ゼロ被害とも重大な埋まりとも断定できない。
* **Enemy自身の残りは小さかった。** 回復・slideが疑われた移動の終了後を計測し、Aで最大約0.00726 px。以前の人工条件の2.91 pxを通常プレイの深さとして扱わない。全Enemyの連続軌跡を独立した幾何ソルバで検証したわけではない。

8回だけで重大判定すると、Fの8件のうち未実行時間0の4件まで障害に数えてしまう。未解消終了、強制通過、リセット位置への到達も別物である。今回の主測定は未解消終了・強制通過を導入せず、全試行で予定7,200更新を実行した。Pは未解消で終了せず、球の不在時間として待機を計上した。

### 時間と参照判定の信頼範囲

標準接触には、元の開始変換・motion・margin・例外を使う読み取り専用 `body_test_motion()` を追加し、safe fractionからその照会の移動時間を調べた。対象不一致は不明扱いとし、主54試行では0だった。独自のhit.timeと標準の実移動分を足し、自由な残り経路を足して更新時間との差を記録した。

これは**現行が実行した区間に対する補正を除いた経路時間の診断**である。時間を直した場合の再接触・板の姿勢まで再計算した正解軌道ではない。標準ラッパーの回復後投影も含むため、`travel−velocity×safe_time` は実効的な非時間変位であり、エンジン内部の未加工回復ベクトルそのものとは限らない。

Aで1 µs超の差は57更新、合計約104.37 ms。そのうち8上限の2更新は合計6.07 ms。半更新超の差は4更新だった。旧ログのtravel投影による残り時間を、真の時間として再利用していない。

検出の高密度計測も独立性を点検した。主測定の4096/2048時刻検査は本番と同じ内部判定を使うため、正解ではなく候補抽出とする。A/S・保持809の更新2447には、球が左の範囲外にいるのに本番内部判定が「内部・深さ約83 px」と返す瞬間が混じった。**B/B＋4の漏れというラベルを撤回した。** これは高密度参照の誤報であり、本番Bがその瞬間に誤打球した証拠ではない。

別の凸四角形の外積・距離計算で接触存在を調べる [独立参照](../tests/value_reference.gd) を作り、16384/8192時刻で以下を照合した。接触位置・応答属性は確認した幾何接触時刻に既存計算から取り出す。

| 実シーンで採取した同一の直前状態 | 検出B | B＋4 | 独立参照 |

| N・保持809・更新503、現行打球条件 | 2.500 ms、通常反射 | 1.719 ms、打球 | 1.668 ms、打球 |
| 同じ状態、3条件打球 | 打球、速さ約1,068 | 打球、約1,320 | 打球、約1,336 px/s |

### 長時間再現の限界

同一条件の再実行も調べた。保持A113の同一呼び出し再実行では、最初の異なる1秒チェックポイントは17秒、位置差約0.0137 px。その後拡大し、24 px超補正が2件と5件に分かれた。別の同一呼び出し2回は120秒の状態・件数が一致した。原因を単なる乱数種の相違にできず、従来調査で見つかった標準接触の小差の増幅と整合するが、エンジン内部の発生原因までは特定できていない。

観測あり／なしでも8対中6対は1秒ごとの位置・速度・敵数・ミサイル数・稼働状態が120秒一致した。保持A/Nの2対は分岐した。4,644一更新の観測版／軽量版は所定の誤差内で一致している。長い軌道の非一致を隠さず、全体件数やCPU差を方式の因果効果へ使わない。保存入力とseedは再試験可能だが、長時間のビット一致までは保証できない。

### 実測CPU：同じ状態からの球1更新

比較には観測・参照・周囲計測を外した [軽量候補](../value_candidate.gd) を作った。既存4,644入力×5方式で同じ開始位置・速度へ戻し、各1回ウォームアップ＋3回計測。条件順は反転する。準備・形状変更・参照計算は時間外。A/Sは元のPinballMotionを直接使う。

以下は実シーンと同じ半径24・60 Hzの336入力だけ。全体には人工的な辺・角・小半径・30/120 Hzもあるため分けた。球1更新であり、描画やEnemy全体の時間ではない。サンプルは少なくµs単位で揺れるので厳密な性能保証や倍率へ使わない。

| 方式 | 全336：中央値 / p95 µs | 非接触186：中央値 µs | 接触150：中央値 / p95 µs |
| --- | ---: | ---: | ---: |
| A | 64 / 122 | 43.5 | 83 / 150.5 |
| N | 46 / 85 | 46 | 45 / 89.5 |
| S | 64 / 135.6 | 44 | 105 / 172.5 |
| B | 47 / 88.6 | 47 | 47 / 89.5 |
| F | 73 / 116 | 54 | 81 / 138 |

N/Bは初期判定が増える一方、上向き16探索と後続の補正接触を減らすため、接触時には軽くなった。全更新で必ず高速という意味ではない。B＋4のB比は接触群中央値で約34 µs、非接触群で約7 µs増加。このPCの1球では過大なCPU負荷を示していないが、20球へ単純比例した値は測っていない。

全体の `main.advance()` は、軌道が一致した自己反応113の観測なし試行で、A中央値95・p95約207・p99約306・最大514 µs。Bは101/215/312/630、Fは105/230/335/610 µs。方式間では球の軌道・敵数が違うので、この差を検出方式だけの追加費用としない。保持B/Fではそれぞれ中央値438/339 µsで、比較環境の違いを示す。

同じ方式の観測あり／なしが一致した自己反応4対では、観測込み中央値は112/113/114/119 µs、なしは95/99/101/105 µs。診断の費用を本番候補へ混ぜていない。1秒ごとの状態一致は全更新のビット一致証明ではないため、追加費用の参考値とする。起動後最初の10秒を全体CPU集計から除外したが、発生件数の観測時間には含めた。CPU固有名は取得できず、環境識別はAMD64 Family25 Model97 Stepping2、16論理CPUまで。

## 3. 費用対効果の評価

**効果を実測した範囲が最も明確なのは新接触の分離方向である。** 食い込み数pxを下面から上面へ抜く処理を、接触側へ数px出す処理へ変える。最初の検出・返球を変えず、余分な補正を減らせる。コードの依存は主に共通移動と板の幾何にとどまり、Enemyの群衆管理や壁を作り直す必要がない。

3条件は既に選ばれた仕様を簡潔に表す変更であり、それ自体を反復対策の効果に数えない。B＋4は速度・接触時刻の局所精度へ効き、CPUも小さい。しかし現在の3条件に残る漏れを通常の半径24でどれほど減らすかは測れておらず、必須とする根拠が足りない。

時間分離・同時刻Enemy判定には技術的な正当性があるが、現在の通常観測で最も大きな被害だった93 px補正を直すためには不要である。旧clock単独悪化もあるため、単純な正誤修正として投入せず、同状態の再現と反復の結果まで評価する必要がある。Enemy移動区間、複数面拘束、深い安全探索を最小構成へ自動的に積み上げない。

Pのような小さい実装にも大きな仕様費用がある。数行の待機を追加して、球が3秒以上出ないゲームにするのは低コストと呼べない。深い復帰の「どこへ出すか」も同様で、位置の飛び・通過・敵の移動を仕様として評価する必要がある。

長時間件数の比較には再現限界があるため、N/Bの上限0/1、Fの8をそのまま順位へ変換しない。現状維持を含め、未検証の候補には根拠のない総合点・工数日数・速度向上率を付けない。

## 4. 推奨する最小構成

1. **検出B、停止板のGodot標準、③、共有8接触、返球・ダメージを維持する。** 全体の追加時間分割や球同士の衝突は追加しない。
2. **承認済み3条件と、新接触のみ法線分離を本番導入の最小候補にする。** 完全に非接触だった更新開始・区間開始を確認できる接触だけ、深さ＋既存0.15 pxを法線へ出す。初期重なり・内部解除の未決定規則をここへ混ぜない。
3. **深い復帰とまれな一時反復は残件として明記する。** 現時点で安全探索、無期限延期、Enemyの押し退け、複数面ソルバを常設しない。今回の観測はそれらの実装費用を正当化するほどの長期停止を示していない。
4. **B＋4は選択可能な次候補にとどめる。** 3条件の同一状態で残る返球速度差を画面で確認し、許容できない場合に採用範囲を検討する。これは③復帰の解決にはならない。

最低限の改修でも全問題を解決したとはしない。残す症状がユーザーに許容されるまで、本番反映は行わない。

## 5. 残る判断と、次の検証の優先順位

| 優先 | 次の確認 | 判断基準 |
| --- | --- | --- |
| 1 | 93 pxの実シーン接触を同じ直前状態でA/N/Bへ与え、表示して確認 | 新接触の返球を維持し、対象板へ残らず、他物体に深い押し込みを新設しない。過去4,644条件の一更新証拠を実シーン代表例でも確認する |
| 2 | 本番相当の操作録画を採取し、重大補正・停滞の前後だけを保存 | 自動操作でなく人間の反応でも問題になるか。球稼働時間・接触報告・落下との時間関係を併記する。数十分未発生で存在しないと断定しない |
| 3 | 通常シーンのEnemy反復の2直前状態と、半更新超の時間差4更新を局所再生 | 同時刻判定／時間分離を単独・組で比較。位置回復と実反射、返球・ダメージを維持し、実際の未実行経路や停滞を減らすか。測定構成を変える前の状態一致を必須とする |
| 4 | 3条件の速度差と残る小半径2件をB/B＋4で再確認 | 漏れ・不自然な返球の実害に見合うか。30/120 Hzの既知405/465/525、近接84配置で追加の打ち切り・押し込みを許容せず報告する |

ユーザー判断が必要なのは、①位置変更の許容、②下降中の通過継続の可否、③再生成で待てる時間・別位置の可否、④Bと高精度接触の返球速度差の許容である。今回24 pxを数えたことやPの待機結果から、採用値を勝手に決めていない。③解除仕様が未決定でも新接触の局所修正の価値は評価できる。

技術的な未確定事項は、長い標準接触軌道の差の発生原因、通常シーンでの全数の独立した打球漏れ率、小さな新規干渉の深さ、他PC・描画込みの費用である。これらが必要な採用判断では、今回の数値だけで決定できない。

## 6. 本番反映した場合の見通しと検証

**最小候補なら主な本番変更は2ファイルを想定する。** `pinball/table_flipper.gd`の打球述語・強化表面速度、`pinball/motion.gd`の更新開始状態と新接触分離。既存のループ内時刻を使えば、実験の時刻追跡アダプタをそのまま複製する必要はない。新しいEnemy状態・群衆規則・main更新順序は不要。変更行数の確定や実装工数の見積もりはまだしていない。

初期重なりを維持するため、下降復帰や真上補正の残存を解決済みとしない。最終位置が変わるため、その後の敵ダメージや落下が変わり得る。これを打球仕様の同等性と混同しない。将来、時間分離とEnemy同時刻判定まで採用するなら、球の応答入口・Enemy状態・mainの受け渡しへ依存が広がり、別の改修単位として検証する。
