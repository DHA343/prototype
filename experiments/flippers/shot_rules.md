# 打球条件の整理（2026-11-22）

対象は `flipper` ブランチの実験。ユーザーによる操作感同等の確認後、3条件を実験上の打球仕様として固定した。本番への採用は未決定で、`pinball/`・`main/`・Enemyは変更していない。

## 分類

「物理的に必要」は、接触して近づく相手に応答するという現在の接触モデル上の必要性を指す。強化打球の方向・威力・上昇限定などのゲーム仕様まで物理法則から必然とはしない。

| 条件・数値 | 分類 | 根拠・今回の扱い |
| --- | --- | --- |
| 球が接触している | 物理応答の前提／今回のユーザー指定 | 単一四角形と円の接触を維持 |
| 球と面の相対法線速度 < 0 | 物理応答上の条件／今回のユーザー指定 | 離れる球へ新たな反射を加えない。球が静止していても面が追いつけば対象 |
| 回転速度×上昇方向 > 0 | ユーザー指定の実験仕様 | 上昇時だけ強化打球するゲームルール。保持・下降でも通常反射は残す |
| 上辺を打球面とする | 3条件とともに確認した実験上の面定義 | 既存の上辺判定を使用し、根元・先端の端点も含めると事前に明示。本番への反映は別判断 |
| 上辺からの距離二乗 < 0.000004 | 暫定的な数値 | 距離約0.002 px。接触点を上辺に分類する既存の許容差として固定 |
| 法線と上側方向の内積 > 0.5 | 未承認の設計判断＋根拠不明の数値 | 60°未満に制限。最初のコミット2c2c38cに既に存在。60°の選定理由・ユーザー承認は不明。候補では不使用 |
| ローカル接触点X > 0 | 未承認の設計判断 | 丸い根元が壁につながるため背面側で強化打球しない、というコメントあり。固定四角形への継続適用の承認根拠は不明。3条件候補では不使用 |
| 位置別の方向・威力、反発、速度上限 | ユーザー指定の維持対象 | 現行の返球計算と設定値を使用。今回調整しない |
| 返球方向と法線の内積 > 0 | 既存の方向補正の保護判断 | 設定方向が面の内向きなら物理反射を使う。打球の有無を決める条件ではない。維持 |
| 打球後は下降まで左右を通す③ | ユーザー指定・採用済み | 対象別管理、通常反射・回復も無効化。変更しない |
| 重力適用後Y速度 > 1 px/sで③解除 | ③を実現する現在の数値 | 本来の「下降」と数値境界は分けて記録。今回変更しない |
| 接触深さ > 0.01 px | 暫定的な検出用数値 | 離れる向きでも重なりを候補として返すための値。打球には別途相対接近が必要 |
| 相対接近速度 > 30 px/s | 暫定的な通知用数値 | 接触通知のしきい値。強化打球の最低速度ではない |
| 衝突余裕0.03 px | 数値計算上の余裕 | Godot標準クエリ。今回固定 |
| 分離余裕0.15 px／探索16回 | 暫定的な数値・回数 | 上向き分離の既存実装。対照・打球条件候補では固定 |
| 最大8接触／残り時間1 µs未満で終了 | 暫定的な数値・回数 | 反復・終了条件であり打球の選別条件ではない。対照・打球条件候補では固定 |
| 約4 px走査／回転終了で区間分割 | 検出方式の現行構成 | 今回変更せず、将来の確認項目として保持 |

## 比較する打球条件

1. `current`：現行条件をそのまま使用。
2. `without_angle`：上昇・上辺・根元X・相対接近を使用し、60°条件を使わない。
3. `three`：上昇・上辺（両端含む）・相対接近だけで打球する。

標準接触と独自接触で同じ上辺定義を使う。現行の標準側 `is_striking()` 自体にはTableFlipperの上辺判定がなかったが、現行Bの停止中は上昇条件が成立しない。この違いを今回の本番不具合と断定しない。

打球は単なる名前ではなく、強化用の表面速度、位置別の返球方向、③の開始を伴う。新たに打球になる接触では、強化用速度も新しい判定から計算し直す。通常の物理表面速度は変えない。

実験部品は親の接触計算を再利用する。親では従来の60°等も一度計算されるが、候補の打球選別には使用しない。これは幾何計算を変えずに仕様だけ比較するための実装であり、演算数を最小化した本番実装とは扱わない。

回転終了ちょうどのサンプルに渡す角速度や、開始重なり・角の面分類には既存実装の境界が残る。今回、走査間隔・回転区間の分け方・分離・反復を打球条件と同時には変更していない。

## 前回の分離・反復の独立した比較

- `normal_new_only`：打球条件は現行のまま。更新開始時と現在の移動区間開始時の両方で幾何的に非接触だった場合に限り、最初の接触を法線方向へ深さ＋0.15 px分離する。開始時接触・重なり、③解除時に既に内部にいる場合は既存の上向き分離16回を維持する。
- `split_budgets`：打球条件と上向き分離は現行のまま。速度が変化する接触と、速度が変化しない処理を別に数え、それぞれ8回で終了する診断用候補。内側ループの安全上限は16回。接触を無視したり、残り時間を無条件に進めたりはしない。

後者の区分には既存Recorderと同じ速度差0.01 px/sを使用する。この分類を「物理的に真の衝突／回復」と同一視しない。8＋8という予算も未承認の実験値で、本番の8回を変更したものではない。

前回の独立比較では3条件・法線分離・予算分離を組み合わせていない。B＋4／D2の既存手法を使う一部の再現は、接触時刻が原因か調べる診断用だった。

## 今回の3条件と法線分離の組み合わせ

現行、3条件のみ、新接触の法線分離のみ、両方の4構成を比較した。Bの検出・返球計算・③・上向き探索16回・共有の最大8接触を維持し、予算分離は混ぜていない。

同じ球・板について更新開始時と移動区間開始時の両方が非接触ならAとし、独自接触を法線方向へ深さ＋0.15 px補正する。更新開始の接触はB、区間開始だけ接触はC、③解除時に開始接触ならD。Aにも同じ更新内の再接触が含まれ得るため、先行接触・速度変化の履歴は別に記録する。B/C/Dの独自接触は上向き分離、停止板の接触はGodot回復を維持する。

周囲への干渉Eは補正前後・補正経路で観測するだけで、応答は変えない。結果は [組み合わせ検証](evidence/separation_audit.md)。単独の大補正は減ったが、③解除時の大補正、Enemyへの食い込みと打ち切りが残る。Bの接触時刻が原因の新仕様の打球漏れ2件も残る。

`separation_preview.tscn` の初期値は3条件＋新接触の法線分離。1＝現行、2＝3条件のみ、3＝法線分離のみ、4＝両方、R＝球リセット。実験部品 `separation.gd` は履歴・周囲観測を持たない。同じ部品をCPU測定と描画付き実行でも確認した。本番へは適用していない。

## 実験の操作と資料

### 2026-11-23：③解除時の回復比較

3条件＋新接触の法線分離を共通基準に、現行解除、左右の重なりがなくなるまで解除延期、安全な小補正3/6/12 pxを比較した。深い内部の処理を打球条件や反復上限の変更と混ぜていない。安全な候補がない場合はユーザー指定どおり未解消で試行終了し、別方式へ切り替えない。

延期は下降条件と両板との非接触を満たす更新開始時に解除する。安全分離は同時刻の姿勢で、法線・軸方向の少数候補の補正先と補正経路を検査する。位置補正自体は速度や打球を変えず、その後は通常の3条件で応答する。

延期は打ち切りを避ける一方で下降中の通過や未解除を生み、安全分離は上限内では深い内部を解消できなかった。どちらも本番採用しない。詳細は [回復比較](evidence/release_audit.md)。操作用は `release_preview.tscn`（1＝従来B、2＝現行解除の実験基準、3＝延期、4/5/6＝安全分離3/6/12 px、R＝リセット）。本番の③は変更していない。

### 2026-11-23：安全分離の距離上限だけを除外

`release.gd` の `distance_limited` は既定でtrue。falseの構成だけ距離上限を使わず、候補生成・方向条件・経路と補正先の安全照会・候補なし時の試行終了は同じにする。3条件・新接触の法線分離・検出B・共有8接触も維持する。

[距離上限なしの比較結果](evidence/unlimited_audit.md)では近接84配置中81が完走したが、3配置はEnemy・壁や方向条件で候補がなく未解消。249.01 px補正と、分離後の通常接触での反復・干渉も残り、本番には採用しない。安全候補内の最短と、全方向での最短やゲーム上の自然さは区別する。

操作用は `unlimited_preview.tscn`。1＝現行解除、2＝12 px、3＝制限なし。4/5/6で既知3配置、7で最大補正例を再現し、Pで停止・Nで1更新ずつ確認できる。距離制限なしの操作感は未承認で、本番は未変更。

### 2026-11-23：復帰・再接触の原因調査

[原因調査](evidence/causal_audit.md)で、完全分離後も更新開始時の接触履歴によって上向き分離を選ぶ実験分類の問題を確認した。履歴の事実と現在の重なり状態を分ける改善案は未実装。標準判定の回復変位を経過時間へ含める共通処理と、移動Enemyの形状・応答速度の基準も独立した課題とする。3条件・新接触法線分離の本番反映や、③・最大8回・検出Bの変更は行っていない。
