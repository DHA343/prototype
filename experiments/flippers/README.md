## 方式選定に関する検証の限界

元の目的は、すり抜け対策の方式と組み合わせを選ぶこと。今回の再検証より前の試験はmain由来の時間分割・回転途中の姿勢検査・接触後の残り時間再計算を共通基盤として残しており、それら自体の採否を比較できていなかった。比較対象を先に採用済みの前提へ入れたため、その試験だけで方式を選定したとは扱わない。

保存した結果は、各記録に明示した共通基盤の上での局所的な比較・不具合の再現として保持する。「すり抜け0」から厚みや無効化だけの効果を結論せず、③の直後の干渉抑制からすり抜け対策全体の優位性を結論しない。共通移動部品へまとめる移植方針は維持するが、その中に現在の時間分割・姿勢検査・接触反復をそのまま採用する決定にはしない。

この問題に対し、時間分割・検出方法・追加厚みを変えた16構成、応答を含む48条件を比較し、さらに876入力の接触点・時刻・速度・位置への影響と、近接敵での反復上限を調査した。今回の範囲では、全体分割なし＋回転中だけ途中姿勢を検査し、反射後は接触点から経路を調べ直す構成が有力。8回という上限は未確定で、食い込み解消との分離が課題。mainへはまだ移植しない。

無効化だけの③・④の比較は **[comparison.tscn](comparison.tscn)** を実行する。左が「打球後、下降するまで左右を通す」、右が「短時間だけ左右を通す・下降したら即解除」。別々の物理空間で、mainと同じ配置・形状・球設定に同じ入力を適用する。起動直後から再生する。

- P：両方を停止・再開、N：停止中に1/60秒、R：両方リセット。A／左・D／右・Spaceで両画面を同時操作する。
- 「左先端から打球を再現」は、球を左上辺の先端寄り92%へ置き、下向き300 px/sから左右を60 ms押す。その後240 msは両方を離し、通常入力へ戻る。左右の配置差・入力時差を網羅する再現ではない。
- ④の時間は停止中に5〜150 msで変更する。40 msは比較開始用の仮値で、推奨値・採用値ではない。変更は次の打球から反映する。
- 状態、有効／無効、打球数、下降／時間による解除数、速度、最大位置補正を表示する。無効化中は予測線を表示しない。
- 「20球に切替／1球に切替」で両画面の球数をそろえてリセットする。複数球では稼働数・無効化数と全球の最大補正を表示する。球同士は衝突せず、予測線は代表1球のみ。
- 無効化の詳細・残る問題は [suppression.md](suppression.md) を参照。採用方式は未決定で、mainには導入しない。

| 厚み | 元の休止姿勢の最下端から、下へ48 px追加。追加量は調整可能 |

追加48 pxは板全体の厚さを48 pxにする意味ではない。下端は元の休止姿勢から固定し、上辺が上がるほど先端の下側にある判定は深くなる。

赤い半透明部分が実際の四角形。球の半径を加えた仮想の帯ではない。赤い表示は回転ノードから独立させて姿勢を補間するため、左右端・下端が描画補間で揺れない。水色の板の端は従来どおり円弧を描いて左右にも動く。

以前の領域試作にあった根元1,400／先端2,600 px/sを直接指定する返球は、今回の構成には含まない。無効化の実験・候補・未決定事項は [suppression.md](suppression.md) にまとめる。

## 操作

- A／左矢印：左、D／右矢印：右、Space：両方。Spaceはフリッパー専用。
- P／マウスでボタンをクリック：停止・再開。N：停止中に1/60秒進める。
- ポーズ・リセットボタンはキーボードフォーカスを取らない。クリック後にSpaceを押してもボタンを実行しない。
- R／ボタン：球をmainの初期位置へ戻し、フリッパー入力をリセットする。
- 停止中に追加の厚みと球の半径を変更できる。Enter確定・入力欄外のクリックでフォーカスを解除する。
- 単独プレビューに自動フリップは置かない。20球の切り替えは比較プレビュー側、反復試験はCLI側に用意する。
- 右側の最大位置補正は現在の球について記録し、球のリセット時に0へ戻す。

## mainへ移植する際の変更方針（決定）

ボールと同様に動く敵などは、共通の移動・衝突部品を使う構成へ変更する。現在の `preview_ball.gd` にあるフリッパーとの接続処理を、対象の種類ごとに複製して移植しない。

### 移動・衝突の精度に関する前提

目的は、本来当たる対象を取りこぼさず、大まかな位置・状態でゲーム的な打球を行うこと。厳密な接触位置・接触時刻に沿って運動を再現することは必須要件にしない。

初期の実験は、main由来の時間分割（最大1/240秒＋回転量に応じた追加分割）、回転途中の姿勢検査、接触ごとの残り時間再計算（最大8回）を共通に残していた。厚み・無効化の当時の結果はこの共通基盤込みであり、時間分割や接触反復が不可欠と実証した結果ではない。

時間分割と回転途中の検査はすり抜け対策、接触ごとの残り時間再計算は反射後の経路を追い直す処理として分ける。追加調査では全体分割なしの途中姿勢検査が成立した。一方、開始点から計算上の終点へ直接移動する近似は、誤ダメージ・接触漏れを生んだため採用しない。反射後の経路検査は、精密な物理再現だけでなく接触対象を正しく拾うために残す。上限8回が最適という根拠はなく、位置回復の反復と移動の反復を分離して改善する対象とする。

- 共通の移動・衝突部品：移動、壁との衝突、フリッパー判定の呼び出し、打球成立の通知、対象ごとの衝突除外と解除の接続をまとめる。
- フリッパー管理：打球方向・威力、対象ごとの無効化状態と解除条件を所有する。`PinballBall` 固有の型やメソッドへの依存を共通の移動部品との接続へ置き換える。
- ボール・敵などの固有処理：移動の指示、AI、HP、固有能力などを持つ。同じ移動部品を使う種類の追加では、無効化やフリッパー対応を個別実装しない。

独自の移動方式を新設する場合は、その方式を共通の衝突処理へ接続する対応が必要になる。既存の敵すべての挙動変更を決めたものではなく、ボールと同様の挙動を持たせる対象が範囲。具体的なクラス名・ノード構成と移植後の検証は移植作業で行う。現時点では設計方針の記録のみで、共通化の実装・検証は未着手。

## 残る決定・確認事項

| 項目 | 状態・次に必要なこと |
| --- | --- |
| 無効化方式の採用 | ユーザーの意向により③「下降まで」を第一候補として扱う。低速では内部にいる間に下降し、解除後に再打球する例がある。現設定600°/sでも近くの敵を加えた84条件中22条件で内部解除を検出したが、その更新での再打球は0。内部解除と新規打球を区別する。上向きのまま戻る対象・下降しない対象の扱いも残る。④の40 msは仮値のまま |
| 元の軌道変更の改善確認 | [打角・速度を変えた比較](evidence/shot_direction.md)で、右斜めへ打球後、停止した右フリッパーの通常反射により右寄りの上へ変わる現象を再現。通常反射による干渉は無効化なし510/1,800条件、③0/1,800条件。解除後の内部接触は別の課題として残る |
| 返球速度の調整項目 | 現プレビューはmainの物理応答と威力均等化を継承。当初の根元・内側の速度を個別調整する要望に対応する項目は未実装。移植前に調整したい位置・値と現方式で足りるかを確認する |
| 接触の反復 | 接触点から反射後の経路を検査する処理は残す。終点への直線移動は採用しない。単純に上限2回へ減らすと近接敵84配置中49配置で残り時間を捨て、8回でも13配置に残る。上限の最適値ではなく、食い込み解消と経路検査が同じ上限を使う構造を改善する課題として扱う |
| mainへ統合した確認 | 共通移動部品をボールと同様に動く別種類の対象で検証する。敵・バンパー・穴縁・挟み込み、描画と敵の処理を含む負荷は統合後に確認する |

## 検証と保存した記録

現行の検査は [tests/preview_test.gd](tests/preview_test.gd)。mainとの必要な配置の一致、不要な本編ノードがないこと、左右端・下端、固定面の速度0、上辺の法線速度、球半径6/24/36 pxでの分離を確認する。さらに、ポーズボタンのクリック後にSpaceで両フリッパーが動き、ポーズ状態が変わらないことを確認する。

最小構成へ変更後のCLI検証はプレビュー616件で失敗0。mainの既存物理検査は直前の共通コード変更時に4,771件で失敗0。

③・④の追加検査は [tests/comparison_test.gd](tests/comparison_test.gd)。57件で失敗0。実際の先端打球による開始、停止／回転中の通過、下降での捕球復帰、時間切れ、他球への非波及、削除・リセット時の破棄、Spaceとポーズの分離を検査する。厚み内部での期限切れ試験も含むが、見た目やすり抜けが解決済みという判定ではない。詳しい観測は無効化ドキュメントを参照。

複数球の検査は [tests/multiball_test.gd](tests/multiball_test.gd)。20球・50球で28条件、状態分離等を含め252件で失敗0。状態の混線と検出範囲内の板下通過は0だが、④5 msでは内部開始の20球中18球に再打球が発生した。大きな補正・接触反復も残る。[条件と結果](evidence/multiball_guard.md)を参照。

打角・速度を変えた追加検査は [tests/shot_direction_test.gd](tests/shot_direction_test.gd)。無効化なし／③を1,800条件で比較し、別途60条件を2秒追跡。検査5,580件で失敗0。通常反射による元の症状と③の抑制を確認した一方、低速での内部解除後の打球を検出した。[追加検証と接触反復の原因](evidence/shot_direction.md)を参照。

[現設定での復帰確認](evidence/current_guard.md) では、設定を変えずに既存の敵を近くへ置いた条件も追加。敵あり84条件中22条件で内部からの解除を確認し、解除した更新での再打球は0だった。通常プレイの発生率は未計測。
