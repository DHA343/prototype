# System Understanding

コード、構造、アーキテクチャ、または設計を理解・把握するための説明方針。

目的はコードを逐語的に解説することではなく、対象の全体像と重要な関係を正確につかめるようにすること。

## 説明方針

- 関連するコードやドキュメントを確認してから説明する。
- ユーザーがGitHubより新しいコードや変更内容を提示している場合は、そちらを優先する。
- 主要な要素、責務、依存関係、処理やデータの流れを整理する。
- 「何をしているか」だけでなく、重要な箇所では「なぜそうしているか」も説明する。
- コードから判断できない設計意図は、事実のように断定しない。
- 理解に不要な細部を並べず、重要な構造から説明する。
- 必要なら段階的に詳細へ掘り下げる。

## 図の使い分け

図が文章より分かりやすい場合のみ使用する。

- 処理、手順、分岐: Flowchart
- 複数主体の時系列のやり取り: Sequence Diagram
- 状態と遷移: State Diagram
- 階層、依存、接続関係: Mermaidなどの関係図

単純な内容に無理に図を付けない。
ASCIIアートは使用しない。

## 説明に含める内容

対象に応じて、必要なものだけを使う。

- 全体像
- 現在の状態
- 各要素の責務
- 要素同士の関係
- 処理やデータの流れ
- 重要な設計判断とその理由
- 必要な場合はトレードオフ
- 期待どおり動いていると判断する方法

理解確認の質問は、誤解が残りそうな重要部分がある場合だけ行う。
ユーザーを試験することを目的にしない。
